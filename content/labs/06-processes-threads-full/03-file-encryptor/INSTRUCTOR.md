# Instructor Notes: Encrypting Files in Batches

## Purpose

The session's partition idea applied to an array of tasks rather than a region of bytes, and the first exercise where the threads *write*.
It is safe because the file sets are disjoint; the point of the exercise is that the student can say that sentence.

## Things students get wrong

* **`files + i` instead of `files + i * batch_size`**: batches overlap, the first files are XORed by several threads, the last are never touched.
  The one-pass `cmp` check in the README catches the untouched ones; the overlapped ones come out right or wrong depending on timing.
  This is the mistake the Check Your Work is written around.
* **`files[i * batch_size]`**, a `char *`, where a `char **` is needed; the compiler says so.
* **Forgetting `unmap_file()`**: the writes still reach the file, eventually, and the process holds every mapping until exit.
  Invisible on 64 files; ask what happens on 64,000.
* **Checking only the two-pass restore.**
  A file in nobody's batch is unchanged after one pass and unchanged after two, so `diff -r` after two passes says nothing is wrong.
  Students who did the one-pass check first catch this; the README asks them to explain why both checks are needed.
* **Running `gen_files.sh` between the two passes**, then wondering why the files are not restored.
* **`data/*.bin` typed into the student's own shell from `01-shell-chaining`.**
  It has no globbing; use `bash`.

## Verified reference values

| Fact | Value |
| --- | --- |
| `./gen_files.sh` | 64 files, 64 KiB to about 576 KiB each, about 23 MiB in all |
| One pass, batch 8 | 8 threads, 64 files differ from `data.orig/`, none unchanged |
| Two passes | `diff -r data data.orig` silent |
| Batch 10 on 64 files | `64 files do not split into batches of 10`, exit 1 |
| Batch 1 | 64 threads, same result |
| Single-threaded run | about 40 ms; batch size makes no measurable difference at this size |
| `strace -f -e trace=clone3,openat`, batch 32 | 2 `clone3()`, each file opened once, descriptors 3 and 4 reused |

## Practical notes

* `data/` and `data.orig/` are git-ignored and regenerated by the script; they are random, so no two students have the same files, and that is fine.
* The script needs `bash` for `RANDOM` and `((...))`; it says so in its first line.
* Nothing here is timing-sensitive, and the files are deliberately too small for threads to show a speed-up; say so if asked, and point at session 07.
